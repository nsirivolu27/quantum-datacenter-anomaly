Authorized red team engagement RT-2026-11

Ethical hackers test the mainframe with written permission, a fixed scope, and rules of engagement

In scope

  • The first four nodes and the decoy service
  • Test bucket qdc-redteam-test and a canary model artifact
  • One test recovery point in the backup vault
  • Six tests over about two simulated minutes

Out of scope

  • Production datasets and approved models
  • Other tenants and shared services
  • The provider's own infrastructure
  • Any real data leaving the environment; canary data only

Rules that come from AWS policy

  • No denial of service, simulated DDoS, or port, protocol, or request flooding
  • No Route 53 zone walking, DNS hijacking, or pharming
  • Command and control testing needs prior authorization from AWS
  • Vulnerabilities in AWS services go to AWS Security within 24 hours

AWS penetration testing policy. On premises sites follow their own written authorization.

Deconfliction

  • Testers connect through an audited session gateway, so their source is known
  • The security team still sees every finding, labeled authorized, and does not escalate it
  • A stop word halts testing immediately
  • Each test has an expected result; gaps become fixes, not blame
