Follow the evidence boundary

Network records establish endpoints, timing and byte counts. They do not identify the process, decrypt TLS, or prove which file moved.

Join workload identity and API access logs to a protected artifact manifest. A denied request demonstrates a policy decision; an integrity mismatch means content differs from its trusted reference.

No integrity checks recorded means unknown verification coverage, not “all data verified.” These browser events illustrate those joins; they are not signed evidence.

Collection coverage simulated control state

Production collection must also measure packet loss, exporter scrape errors, dropped log records and clock skew. Those quantities are not measured here. A quiet event stream is not proof that a sensor is healthy.

Investigation sequence

  1. Check sample age, expected coverage and time alignment before trusting a flat chart.
  2. Identify the GPU, rack, approved job, owner and workload phase. Compare with peers doing equivalent work.
  3. Separate hardware degradation from unauthorized activity using error counters, thermal limits, job history and network evidence.
  4. Correlate the destination, access decision and artifact version. Confirm process identity with host telemetry; this demo has no process collector.
  5. Preserve evidence, assess job impact, and obtain response authorization before isolating real infrastructure.

How this GPU compute cluster operates

“Mainframe” here means the simulated GPU hall. Each rack contains four independent GPU workers. The browser models compute, data movement and security events on a one-second clock; the diagram is a view of that state.

Admit a workload

A scheduler assigns an approved job to available GPUs. Job ID and owner provide the authorization context. A busy GPU without a matching job needs investigation, including stale scheduler records.

Stage the data

The worker requests data from the private storage endpoint. PCIe moves data between host and device; VRAM holds tensors and working state. Capacity used and memory activity answer different questions.

Compute and synchronize

GPU kernels execute; workers exchange results over a local GPU interconnect or the network fabric. Fetch, compute, synchronization and checkpoint phases have different expected activity.

Observe the hardware

Collect temperature, board power, memory, clock state and error counters. Join device UUID, host, rack, job and timestamps. Here a generic 16 GiB / 300 W profile is illustrative, not a particular GPU specification.

Correlate security evidence

Compare approved jobs and peers with connection metadata, decoy hits and access logs. The temperature residual is a transparent formula; the browser does not run the repository's machine-learning models.

Investigate and recover

Distinguish cooling or link faults from workload misuse. Preserve the timeline, constrain access after review, validate artifacts, and verify recovery with new observations. A falling alert count alone is insufficient.

VRAM GiB / capacityMemory allocated on the device, distinct from memory activity.Check allocation failures, batch size and application memory growth. High allocation can be intentional.
Temperature, watts, MHz, clock reasonThermal and power behavior with the current clock state.Correlate with load and neighboring GPUs. Production limits are device-specific; this page's 85 °C / 300 W values are demo assumptions.
PCIe / NVLink RX and TX, GB/sTransfer rate in each direction from the GPU's perspective.Link throughput is not internet egress. Compare synchronization phase, retry deltas and topology. PCIe includes protocol overhead; NVLink profiling rates exclude headers.

Connect real telemetry later

DCGM Exporter → Prometheus for supported device fields; scheduler inventory for job ownership; Zeek for connections; OpenCanary for decoy contacts; application audit and protected manifests for data integrity.

On AWS, the corresponding design uses GPU metrics in CloudWatch, selected VPC/Zeek visibility, CloudTrail data events, and versioned S3 artifacts protected with IAM and KMS. None of those services is connected to this page.

Data contract and measurement limits

One generated sample per device per simulated second. Fresh means age ≤3 simulated seconds. Fleet values omit older samples and display coverage. Trends retain 120 seconds; the heatmap retains 60.

Memory is GiB (2³⁰ bytes); network rates use MB/GB (10⁶/10⁹ bytes). Rates and event counts have separate units. Missing values remain unknown. Counter deltas require two observations and can be partial after an interruption.

Export includes the selected GPU, observations, filtered findings, related flows, global access events, active controls and simulation assumptions. It is a diagnostic snapshot, not a forensic chain of custody.

Authorized red team engagement RT-2026-11

Ethical hackers test the mainframe with written permission, a fixed scope, and rules of engagement

In scope

  • GPUs gpu-01 to gpu-04 and the decoy service
  • Test bucket qdc-redteam-test and a canary model artifact
  • One test recovery point in the backup vault
  • Six tests over about two simulated minutes

Out of scope

  • Production datasets and approved models
  • Other tenants and shared services
  • AWS's own infrastructure
  • Any real data leaving the environment; canary data only

Rules that come from AWS policy

  • No denial of service, simulated DDoS, or port, protocol, or request flooding
  • No Route 53 zone walking, DNS hijacking, or pharming
  • Command and control testing needs prior authorization from AWS
  • Vulnerabilities in AWS services go to AWS Security within 24 hours

AWS penetration testing policy

Deconfliction

  • Testers connect through Session Manager from an approved bastion, so their source is known
  • The security team still sees every finding, labeled authorized, and does not escalate it
  • A stop word halts testing immediately
  • Each test has an expected result; gaps become fixes, not blame
